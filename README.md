# Pandora Arena

판도라의 힘으로 싸우는 1대1 온라인 대전 아레나. Unity 클라이언트 개발자 포트폴리오입니다.

2D RPG 「미니판도라즈」의 판도라·전투 규칙(피해 공식, 스킬 데이터)을 가져와 3D 실시간 대전으로 옮겼습니다. 혼자서는 AI 상대와, 둘이서는 방 코드나 빠른 매칭으로 웹·PC·안드로이드 어디서든 같은 방에서 싸웁니다.

- 포트폴리오 페이지: https://hyeonsik-game-portfolio.vercel.app/projects/minipandoras-arena/
- 플레이 영상(72초): https://youtu.be/2qQKSi5xhaM
- 개발: 1인 개발. 코드는 Claude Code와 함께 작성했습니다.

| 항목 | 내용 |
|---|---|
| 엔진 | Unity 6.3 (6000.3.25f1), URP |
| 네트워크 | Netcode for GameObjects 2.14, Unity Relay(Multiplayer Services 세션) |
| 서버 | Unity Leaderboards, Cloud Code(JavaScript), Cloud Save |
| 플랫폼 | 웹(WebGL), Windows, 안드로이드 |
| 코드 | 게임 C# 73개 파일 + 에디터 도구 3개, EditMode 테스트 8묶음 + Cloud Code 테스트(node) |

## 만든 것

### 온라인 대전

판정은 호스트 한 곳에서 하고, 참가자는 입력만 보냅니다.

- **상대 보간**: 참가자 화면은 호스트의 0.1초 전을 그립니다. 받은 모습들 사이를 메우고, 받은 범위 밖은 짐작하지 않습니다. 지연 50ms에서 빠르기의 흔들림이 7.99 → 0.96m/s, 멈춰 보이는 프레임이 34% → 0%로 줄었습니다.
- **내 입력 예측**: 내 인물은 호스트를 기다리지 않고 바로 움직입니다(조이스틱에서 움직임까지 27ms, 호스트의 답은 170~200ms). 호스트가 알려 온 자리와 어긋난 만큼 몇 프레임에 나눠 고칩니다(평균 0.077m).
- **같은 결과**: 한 방향 지연 50·100·150ms, 손실 0·5·10%에서 한 판을 끝까지 싸우고, 두 화면의 대전 기록(맞음·피해·남은 체력·쓰러짐)을 줄 단위로 견줘 모두 같았습니다.
- **Relay**: 웹은 WebSocket, PC·안드로이드는 DTLS로 붙어 같은 방에서 만납니다. 상대가 끊기면 5초 안에 알리고 혼자 하기로 돌아갑니다.

### 믿을 수 있는 순위표

- 두 사람이 각자 보고한 결과가 서로 맞을 때만 Cloud Code가 Elo 점수를 적습니다. 플레이어는 접근 정책으로 순위표에 직접 쓸 수 없습니다.
- 두 보고가 거의 같은 때 와도 Cloud Save의 쓰기 잠금으로 한 판을 한 번만 정산합니다.
- 5000위까지 100줄씩 불러 오고, 보이는 줄(9줄)만 만들어 스크롤할 때 돌려 씁니다.

### 카메라와 몸짓

- **대전 카메라**: 조이스틱의 위가 늘 화면의 위가 되게 각도를 고정한 쿼터뷰. 두 사람이 멀어지면 물러나고, 맞거나 끝타를 맞히면 흔들립니다.
- **관전 카메라**: 넓게·옆·어깨 너머 컷을 돌다가 치명타·끝타를 맞거나 쓰러진 사람이 생기면 그 사람을 가까이 담습니다. 컷 시간은 쓰러짐의 느린 화면에서도 늘어나지 않게 잽니다.
- **몸짓**: 무료 모션을 휴머노이드로 리타깃하고, 상대를 보는 시선 IK, 스킬을 쏘는 손을 판정 자리로 뻗는 조준 IK, 머리카락 스프링 본을 더했습니다.

### 그림

- 셀셰이딩과 외곽선 셰이더 한 벌로 인물·투기장을 묶었습니다. 외곽선이 조각 이음매에서 갈라지지 않게 부드러운 법선을 들여올 때 굽습니다.
- 스킬 효과(불꽃·악마·차원, 넷씩)는 툰 효과 셰이더로 직접 그렸습니다.
- 투기장·소품은 Blender Python 스크립트, UI 그림은 Python(Pillow) 스크립트가 정본입니다.

## 코드 구조

폴더가 곧 네임스페이스이고, 층을 이룹니다. 아래 층은 위 층을 모르고, 위로 알릴 때는 C# 이벤트를 씁니다.

```
Input → Combat → Fighters → Skills → Cameras → UI → Controls → Duel → Net → Ranking
```

- 인물·스킬·한 판의 코드는 네트워크를 모릅니다. 온라인은 그 위의 `Net` 층이 잇습니다. 그래서 혼자 하기와 온라인이 같은 코드로 돕니다.
- 클래스는 `sealed`, 필드는 `private [SerializeField]`, Manager·이벤트 버스·Base 클래스 계층은 만들지 않았습니다.
- 게임 수치는 ScriptableObject 데이터가 정본입니다.
- 매 프레임 메모리를 할당하지 않습니다(피해 숫자·목록 줄·스냅숏 칸을 돌려 씀). 프로파일러로 1500프레임 동안 할당 0바이트를 확인했습니다.
- 자세한 지도와 결정 기록: [`Docs/ARCHITECTURE.md`](Docs/ARCHITECTURE.md)

## 테스트

EditMode: 3연격 이어 치기, 2D판과 같은 피해 공식(35가지), 바닥 판정, 화상 타이머, 보간 버퍼, 재생 시계, 예측 보정, 닉네임 규칙. Cloud Code: 보고 일치·Elo 계산·정산 차례(`node --test Tools/CloudCode/report_duel.test.js`).

## AI 도구와 함께 만든 방법

코드·셰이더·Blender 스크립트·UI 그림 스크립트는 AI 도구(Claude)와 함께 썼습니다. 제가 정한 것: 범위와 단계, 네트워크 도구, 그림체 판정(코드로 지은 인물은 거절하고 제 아바타로 바꿈), 점수 규칙, 각 단계의 통과 여부. 단계마다 관문을 두고(그림체 → AI 상대와 한 판 → 지연이 있어도 두 화면이 같음) 영상과 기록으로 확인한 뒤 넘어갔습니다.
